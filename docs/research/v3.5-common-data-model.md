# 3.5 全局数据结构调研

> 调研日期：2026-08-10
>
> 范围：通用战斗机制、已实装五星共鸣者、五星武器、五星声骸与合鸣效果

## 来源策略

- 主要来源：库街区《鸣潮》官方 WIKI 的共鸣者、武器、声骸和合鸣目录。
- 指定社区交叉验证：共鸣者同时对照鸣潮 BWiki 与[鸣潮 Wiki* 共鸣者列表](https://wikiwiki.jp/w-w/%E5%85%B1%E9%B3%B4%E8%80%85%E4%B8%80%E8%A6%A7)；武器、声骸和合鸣只对照鸣潮 BWiki。WikiWiki 的[伤害计算式](https://wikiwiki.jp/w-w/%E3%83%80%E3%83%A1%E3%83%BC%E3%82%B8%E8%A8%88%E7%AE%97%E5%BC%8F)仍可作为通用机制研究资料，但不作为后三类实体的必需验证源。
- “阅读全部”用于归纳公共 schema 与机制类别，不表示把社区页面原文或图片复制进仓库。具体数值进入正式数据集前仍需逐字段核对。

## 通用战斗机制

普通伤害至少包含基础攻击/生命/防御缩放、技能倍率、倍率提升、伤害加成、伤害加深、暴击、其他独立乘区、防御与抗性。相似措辞不代表相同乘区；同名效果的叠加方式和不同名效果的乘算关系必须由效果类型明确表达。

攻击力由角色与武器的满级基础攻击组成基础值，再应用百分比与固定值。防御区需要角色等级、敌人等级、防御无视和防御降低；抗性区需要基础抗性、减抗和抗性无视。异常效果伤害使用另一套等级依赖公式，不能复用普通技能伤害入口。

## 五星共鸣者共同点

- 固定数据：90 级基础生命、攻击、防御、属性、武器类型、共鸣能量上限和固有属性节点。
- 技能骨架：常态攻击、共鸣技能、共鸣回路、共鸣解放、变奏、延奏及固有技能；一个动作可包含多次命中、不同伤害标签、资源变化和派生动作。
- 可变构筑项：共鸣链 0–6。正式计算器不提供等级、突破或技能等级输入，统一使用 90 级与满技能。
- 角色专属资源、协同攻击、召唤物、异常效果和特殊形态差异较大，应引用受控 mechanic ID；公共实体 schema 不承载任意脚本。

## 五星武器共同点

- 五类武器共享“90 级基础攻击 + 90 级副属性 + 谐振效果”结构。
- 谐振阶范围为 1–5，主要改变被动数值；不改变武器类型和满级基础面板。
- 被动需结构化记录触发事件、条件、作用对象、效果类型、数值、层数上限、持续时间、触发间隔、刷新方式及离场行为。
- 用户只选择武器和谐振阶，不调整武器等级。

## 五星声骸共同点

- 等级固定 +25，主声骸技能固定最高阶；COST 为 1、3 或 4，五个位置通常受总 COST 12 约束。
- 每个位置包含按 COST 限定的随机主词条、按 COST 固定的副主属性，以及最多五条独立副词条。副词条在 +5/+10/+15/+20/+25 解锁，数值不会随声骸等级继续成长。
- COST 4 主词条常见生命%、攻击%、防御%、暴击率、暴击伤害和治疗效果；COST 3 还包含共鸣效率与六属性增伤；COST 1 为生命%、攻击%、防御%。合法表必须版本化。
- 只有首位声骸保存具体名称、主动/常驻技能和技能来源；其余四位按已确认产品需求只保存 COST 与全部实际属性，不保存声骸名称。

## 合鸣效果共同点

- 合鸣由声骸组合激活，与声骸等级和稀有度无关。
- 阈值不是固定的 2/5 件：现有数据包含 1 件、2 件、3 件和 5 件结构，因此使用数据驱动的 `thresholds[]`。
- 效果模型需覆盖触发事件、条件、作用对象、效果类型、数值、叠层、持续时间、内部冷却、刷新/覆盖、离场保持和同名效果不可重复等规则。
- 部分新合鸣绑定版本专属状态或异常效果，数据只能引用领域枚举或受控 mechanic ID。

## 对 Phase 1 的直接影响

1. 移除角色等级与技能等级输入，改用 90 级满技能数据。
2. 武器固定 90 级，新增谐振阶 1–5。
3. 声骸固定五星 +25；主声骸技能固定最高阶；COST 由位置数据决定而非自由养成选项。
4. 每个副声骸位从“一个副词条汇总”升级为最多五条带类型的实际副词条。
5. 新增共鸣链 0–6，并让链效果通过声明式 effect 或具名 mechanic 进入模拟器。
6. 把伤害加成、倍率提升、伤害加深和其他独立乘区拆开；补充防御无视/降低。抗性采用负抗、0–80%、80% 以上三段公式，其中高抗分支标记为 `community-consensus`，特殊完全免疫单独建模。
