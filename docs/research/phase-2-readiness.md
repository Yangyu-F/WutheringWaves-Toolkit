# Phase 2 入口检查

> 检查日期：2026-08-10
> 结论：Phase 1 已达到验收标准；Phase 2 功能实现开始前需先完成时序规则调研与 ADR。

## 已满足

- 3.5 单共鸣者纵向切片已覆盖秧秧、千古涑流、飞廉之猩和啸谷长风。
- 官方中文实体名、技能名、武器效果名、声骸命中动作与合鸣档位已复核。
- 基础伤害、防御、抗性、暴击、增伤、易伤、倍率加深与独立乘区已分层实现并有边界测试。
- 动作编译、声明式效果、叠层/过期、声骸词条合法性与金标准结果已有自动化测试。
- 模拟核心与 Vue/Pinia/DOM 解耦，可作为 Worker 和时间轴的基础。

## Phase 2 开始前的必要决策

1. 确认游戏逻辑时间单位、实际命中帧和动作持续时间；当前 `offsetMs` 只是稳定排序占位值。
2. 定义同一时间戳下命中、Buff 生效/过期、资源变化和动作切换的显式优先级。
3. 记录秧秧动作的可取消窗口、前置条件、冷却与资源约束，并形成可复现的测量 fixture。
4. 用 ADR 确认时间轴交互采用 Pointer Events 自研还是引入拖拽库，同时约定键盘精确编辑与撤销/重做数据模型。
5. 在开始本地持久化前确认 IndexedDB 封装、schema 版本和迁移边界。

## 推荐的下一步

先将“时序规则与秧秧动作测量”作为 Phase 2 的入口任务，产出 ADR 和离线 fixture。这些规则确定后，再实现多轨时间轴、Worker 协议和持久化，可避免 UI 先行后反复改动核心事件模型。
