# Phase 2 实施复核

> 首次检查：2026-08-10
>
> 最近复核：2026-08-12
>
> 结论：Phase 1 已达到验收标准；Phase 2 已进入实现并完成首轮编辑器、项目持久化与模拟联通。

## 已满足

- 3.5 单共鸣者纵向切片已覆盖秧秧、千古洑流、飞廉之猩和啸谷长风。
- 官方中文实体名、技能名、武器效果名、声骸命中动作与合鸣档位已复核。
- 基础伤害、防御、抗性、暴击、增伤、易伤、倍率加深与独立乘区已分层实现并有边界测试。
- 动作编译、声明式效果、叠层/过期、声骸词条合法性与金标准结果已有自动化测试。
- 模拟核心与 Vue/Pinia/DOM 解耦，可作为 Worker 和时间轴的基础。

## 已确定的时序简化

1. 不将逐技能真实命中帧与动作时长作为 Phase 2 门槛。
2. 动作持续时间按伤害段数乘以每段 `50ms` 推导；具体估算系数在 Phase 2 时序 ADR 中集中定义。
3. 首段伤害在动作开始时产生，后续伤害段每隔 `50ms` 产生一次。
4. 所有推导时序标记为 `estimated`，以后可按动作提供实测覆盖，但不要求全量测试。

## 已确定的重叠与取消规则

1. 动作不按战斗类型互斥；编辑器自动把重叠区间放入多个子行，避免遮挡。首版同一共鸣者最多容纳 4 个同时动作，第 5 个会被拒绝并反馈。
2. 用户通过裁剪动作长度取消后半段；裁剪后未执行的伤害、Buff 和资源事件被丢弃，动作开始时已结算的效果不回滚。
3. 同时间戳命中共享命中前快照；`hit-after` 效果不影响同时间戳的其他命中，Buff 结束时间包含端点。

## 已实施的工程决策

1. ADR 0004 确定使用原生 Pointer Events，并保留毫秒数值输入作为键盘可访问的精确编辑路径。
2. 撤销/重做使用有界内存历史，一次拖动只产生一个历史节点。
3. 多项目使用 IndexedDB 保存；带 schema 版本和 Zod 校验的 JSON 用于导入导出。

## 推荐的下一步

效果目标归属和 5 行效果区已经接入。下一轮按以下顺序推进：

1. 重做最多三名共鸣者的队伍配置结构，并补齐每名共鸣者的武器、首位声骸、其余四个声骸位和属性输入。
2. 为资源、冷却、前置条件和更多声明式效果补齐事件数据及测试。
3. 增加时间轴交互层测试，覆盖拖动、播放头吸附、4 路并发边界、键盘编辑、滚动与缩放；补充窄屏降级验证。
4. 接入第二名共鸣者的纵向数据，验证现有 schema 与队伍效果归属能否自然扩展。
5. 使用真实长轴建立性能基准；仅在主线程模拟影响交互时引入 Worker。

## 延后事项

- 队伍配置需要在后续 Phase 2 中重新设计信息结构，以支持最多三名共鸣者各自的武器、首位声骸、其余四个声骸位置及相关数值；当前单共鸣者纵向切片界面暂时保留，不在本轮局部修补中扩展。
