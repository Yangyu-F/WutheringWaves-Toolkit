# 3.5 武器、声骸与合鸣机制引擎覆盖审计

> 审计日期：2026-08-13  
> 样本范围：官方 Wiki 3.5 候选集中的 89 把四/五星武器、95 个 COST 3/4 满星声骸和 34 套合鸣效果。

## 结论

现有引擎已补齐护盾、多属性缩放、配装/队伍条件、显式切人、技能充能和冷却修改，适合作为三类装备效果的公共基础，但仍不能无损表达全部效果。剩余缺口集中在敌方受击事件、动态属性换算、目标异常历史、期望暴击触发和声骸变身输入。

| 机制类别                                           | 当前能力                              | 结论                                                       |
| -------------------------------------------------- | ------------------------------------- | ---------------------------------------------------------- |
| 常驻攻击/生命/防御、暴击、共鸣效率、属性与技能增伤 | `CombatStats`、`CombatModifiers`      | 可支持；需扩充全部元素和生命/防御面板 UI                   |
| 施放、命中、治疗、变奏/延奏触发                    | action-start、hit-after、switch、条件 | 支持显式切人及 active/self/team/enemy 目标                 |
| 持续时间、叠层、刷新、内部冷却                     | Buff 与 resource 事件                 | 支持常见形式；需为“同名不可叠加”和独立层持续时间补策略字段 |
| 回能和条件消耗                                     | typed resource                        | 模型支持；共鸣/协奏初值与 UI 尚未接入                      |
| 防御/抗性无视和降低                                | 独立伤害乘区                          | 支持                                                       |
| 理论回复                                           | healing event                         | 支持单目标理论值与作用目标                                 |
| 召唤、协同、周期效果                               | generated mechanic event              | 公共承载已建立；逐实体仍需声明触发源、间隔、次数和倍率     |
| 护盾                                               | ShieldResult、shield-gained           | 支持理论生成量、目标、持续时间与获得护盾触发               |
| HP/DEF 伤害缩放                                    | per-hit scalingStat                   | 支持攻击、生命和防御逐段选择                               |
| 队伍与配装条件                                     | team/loadout condition context        | 支持来源槽装备、队伍成员、在场状态和护盾状态               |
| 技能冷却                                           | charge queue、cooldown change         | 支持多充能、缩减、重置、恢复充能及软诊断                   |

## 需要继续扩展

1. **受击与次数消耗**：鸣钟之龟的护盾受到 3 次攻击后消失。当前默认不模拟敌方攻击，因此只能按持续时间统计；未来若允许用户添加受击事件才能精确提前移除。
2. **动态属性换算**：星构寻辉之环按偏谐值累积效率换算全队攻击，部分装备按当前生命、共鸣效率或资源值换算。需要 `derivedModifier` 或受控表达式，而不是任意脚本。
3. **敌方异常和标记**：震谐、霜渐等异常触发及“附加过某效果”需要敌方状态注册表和历史条件。
4. **声骸主动形态**：长按/短按、变身持续攻击与召唤是用户选择，不应自动猜测；应拆成多个官方动作变体。
5. **暴击触发**：高天共奏之曲要求协同攻击命中且暴击。期望暴击模式不能随机决定一次触发，应提供确定暴击条件口径或仅在必暴模式触发。

## 代表性核对

- 栖霞饮露：生命常驻、解放回协奏、异常/治疗双状态及同时持有后的全队攻击；前两类可支持，异常历史和双状态条件需扩展。
- 万物持存的注释、驭冕铸雷之权：护盾触发、内部冷却、叠层和防御无视均已有公共原语。
- 封庭械囿：召唤伤害与首位装配治疗加成；伤害事件可支持，首位装配条件需 loadout 上下文。
- 无常凶鹭：首次命中回能及跨角色延奏增伤可声明；短按/长按仍需拆成不同动作。
- 高天共奏之曲：协同攻击增伤及协同暴击触发全队攻击；派生事件可承载，暴击触发口径仍需确定。
- 失序彼岸之梦：共鸣能量为 0 时生效；资源条件扩展后可直接声明。

因此，不需要为每件装备编写独立模拟器。大部分装备可以继续使用声明式数据；下一步应优先处理敌方受击/异常历史与动态属性换算，少数无法声明的复杂效果再使用受控具名机制。
