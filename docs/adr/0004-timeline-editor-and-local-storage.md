# ADR 0004：时间轴交互与版本化本地项目

- 状态：已接受；Phase 2 首轮已实施
- 日期：2026-08-10
- 复核：2026-08-12

## 决策

时间轴拖动使用原生 Pointer Events，不引入通用拖拽库。动作位置保存为整数毫秒，可通过检查器数值输入和键盘微调精确修改。拖动默认自由定位；动作边缘进入播放头的屏幕阈值时吸附到播放头。缩放只改变像素与时间的映射，不修改项目数据。

时间轴时长提供 30、60、120 秒三档，默认 60 秒。新增动作进入当前可视窗口；“适应窗口”以最后一个动作的结束位置为边界，而不是强制展示完整时长。技能与效果共享一套水平滚动和时间标尺。

计算项目使用 IndexedDB 保存并支持多个方案，当前项目 ID 可留在 `localStorage`。项目与时间轴 JSON 均包含 schema 版本；导入先通过 Zod 验证并限制文件体积、时间轴时长和动作数量，无效文档不覆盖当前状态。存储引擎不泄漏到模拟核心。

## 原因

- 时间轴需要自定义播放头吸附、缩放、并发容量和裁剪语义，原生 Pointer Events 已满足首版需求。
- 键盘/数值输入是完整替代路径，不将拖动作为唯一操作方式。
- 多项目管理是单一计算器产品的核心能力，IndexedDB 提供异步持久化和后续扩展空间。

## 后果

- 编辑操作必须进入有界的撤销/重做历史，拖动一次只创建一个历史节点。
- 时间轴文档状态与缩放、可视范围、当前共鸣者槽等临时视口状态分离；后者不写入项目文档。
- Pointer、播放头、viewport 和键盘交互分别由 composable 管理，schema 与迁移不放在 Pinia store 中。
- JSON 导入导出不包含可执行内容，未知 schema 版本必须拒绝。
- 导入项目生成新 ID，避免覆盖已有方案；导出文件不包含可执行内容。
