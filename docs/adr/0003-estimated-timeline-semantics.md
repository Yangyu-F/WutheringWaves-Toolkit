# ADR 0003：估算时序、动作重叠与取消语义

- 状态：已接受；Phase 2 首轮已实施
- 日期：2026-08-10

## 决策

### 估算时序

Phase 2 不要求逐动作实测命中帧和持续时间。编译器暂按每段 `50ms` 推导动作区间：首段在动作开始时命中，后续每段间隔 `50ms`，动作总时长为段数乘以 `50ms`。所有推导值标记为 `estimated`，未来可由单个动作的实测值覆盖。

### 动作重叠

编辑器不再根据前台、召唤、协同或离场状态判定重叠是否合法。同一共鸣者轨的重叠动作由确定性区间装箱算法分配到多个子行，保证动作块不互相遮挡。首版界面最多容纳 4 个同时动作，第 5 个会被拒绝并显示反馈；该上限是编辑器的可视容量边界，不代表战斗机制不允许重叠。执行方式字段可继续描述机制，但不控制编辑器排布合法性。

### 长度裁剪

取消不创建单独的闪避事件。用户直接缩短动作块的有效结束时间；编译器不再生成裁剪点之后的命中、结束时 Buff 和后续资源事件。动作开始时已经获得的 Buff、已扣除或获得的资源及其他已结算事件不回滚。恢复完整长度时删除裁剪字段，重新采用估算或实测自然结束时间。

### 同时间戳结算

事件按 `(timeMs, priority, sequence)` 稳定排序。一个时间戳内的阶段顺序为：

1. 移除结束时间早于当前时刻的效果。
2. 处理角色切换、动作开始、前置验证与资源消耗；动作编译阶段已过滤裁剪点后的事件。
3. 施加 `action-start` 效果。
4. 对当前时间戳的所有命中使用同一份命中前状态快照计算伤害。
5. 所有命中完成后，再按稳定序号处理 `hit-after` 效果、资源回复和其他派生事件。
6. 处理结束时间等于当前时刻的效果到期与动作结束。

Buff 的结束时间包含端点。`action-start` 效果可以影响同时间戳的命中；`hit-after` 效果不影响同时间戳的任何命中，只会影响之后时间戳的事件。

## 后果

- 时间轴 schema 在动作实例上保存可选的 `trimmedEndTimeMs`。
- 编译器必须在运行模拟前完成裁剪截断和事件优先级分组，不生成机制层面的重叠冲突；4 路并发上限由编辑器输入边界负责。
- 测试必须覆盖任意重叠、裁剪前后的命中/效果/资源、Buff 端点和同时间戳快照。
